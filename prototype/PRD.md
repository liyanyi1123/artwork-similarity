# 艺术品原创登记与相似性核验 Prototype PRD

## 1. 文档信息

- 产品名称：Art Registry（暂定）
- 版本：Prototype v0.1
- 日期：2026-08-25
- 阶段：概念验证

## 2. 产品概述

Art Registry 是一个面向艺术家的艺术品登记网页。艺术家提交作品图片和基础资料后，系统将上传图片与数据库中已经登记的艺术品进行相似性比对：

- 未发现达到判定条件的相似作品：允许登记新艺术品。
- 发现达到判定条件的相似作品：阻止自动登记，并展示候选记录供后续核查。

本阶段只验证用户流程、信息表达和结果反馈是否清晰，不实现真实模型推理、数据库写入、用户身份认证或法律意义上的权属认定。

## 3. 背景与问题

艺术家登记作品时，平台需要降低同一作品、轻微修改版本或高度相似作品被重复登记的风险。现有 CLIP 与 ViT 图像相似性实验可以作为候选技术，用于在登记前检索数据库中的相似作品。

需要验证的核心问题：

1. 艺术家是否理解“先比对、后登记”的流程？
2. 通过或失败的原因是否表达清楚？
3. 检测到相似作品时，展示哪些信息才能支持人工判断？
4. 艺术家是否愿意提交必要的作品资料和声明？

## 4. 目标用户

### 主要用户

- 希望为原创作品建立登记记录的独立艺术家。
- 代表艺术家提交登记的工作室或画廊人员。

### 用户目标

- 快速上传作品并提交必要资料。
- 知道作品是否与数据库中的记录高度相似。
- 在通过比对后获得清晰的登记编号和结果确认。
- 在登记失败时知道是哪条候选记录触发了阻止。

## 5. 产品目标

### 本次 Prototype 目标

- 验证从上传到登记完成的端到端交互流程。
- 演示等待比对、比对通过、发现相似作品和登记成功四种状态。
- 验证双模型结果及阈值信息是否需要向用户展示。
- 为后续接入真实 CLIP、ViT 和艺术品数据库提供界面基础。

### 非目标

- 不进行真实的 CLIP 或 ViT 推理。
- 不上传图片到服务器。
- 不保存用户资料或作品记录。
- 不实现登录、支付、区块链、证书下载或版权交易。
- 不以相似性结果直接判定抄袭、侵权或作品所有权。

## 6. 核心用户流程

1. 艺术家进入“注册新艺术品”页面。
2. 上传作品图片。
3. 填写作品名称、艺术家姓名、创作年份和媒介。
4. 确认原创声明和数据处理授权。
5. 点击“与数据库比对”。
6. 系统展示检索进度。
7. 系统返回结果：
   - 未发现高度相似作品：开放“注册艺术品”操作。
   - 发现高度相似作品：停止登记并展示最相似候选记录。
8. 比对通过后，艺术家确认登记并获得登记编号。

## 7. 功能需求

### P0：本次原型必须包含

| 功能 | 需求 |
|---|---|
| 图片上传 | 支持 JPG、PNG 和 WebP；上传后显示预览和文件名。 |
| 演示作品 | 可直接载入内置图片，便于快速体验流程。 |
| 基础资料 | 收集作品名称、艺术家姓名、创作年份和媒介。 |
| 原创声明 | 用户必须勾选声明后才能开始比对。 |
| 比对进度 | 展示图像处理、数据库检索和规则判定三个阶段。 |
| 通过状态 | 明确显示未发现高度相似作品，并允许继续登记。 |
| 失败状态 | 明确显示发现相似记录，并展示候选作品和相似度。 |
| 登记成功 | 生成模拟登记编号并显示确认状态。 |
| 场景切换 | 原型可切换“未发现相似作品”和“发现相似作品”，用于测试两种路径。 |

### P1：后续 MVP

- 用户注册、登录及艺术家身份验证。
- 图片对象存储与安全扫描。
- 接入 CLIP、ViT 推理服务。
- 向量数据库候选检索和精排。
- 保存艺术品元数据、比对记录和模型版本。
- 相似结果人工复核与申诉流程。
- 登记凭证生成和历史记录查询。

## 8. 暂定判定逻辑

原型沿用当前 WikiArt 实验中的双阈值 AND 逻辑作为演示：

```text
若 CLIP similarity > 0.88 且 ViT similarity > 0.48：
    判定为可能相似，阻止自动登记
否则：
    未发现达到阈值的相似作品，允许继续登记
```

以上阈值仅用于概念演示。正式产品需要：

- 使用独立校准集和测试集确定阈值。
- 记录数据域、模型版本及阈值版本。
- 评估不同艺术类别和媒介下的误报与漏报。
- 对接近阈值的结果设置人工复核区间。

## 9. 页面状态

| 状态 | 用户看到的内容 | 可执行操作 |
|---|---|---|
| 初始 | 上传区、作品资料、等待比对 | 上传并填写资料 |
| 比对中 | 当前步骤、进度条、已检索数量 | 等待 |
| 比对通过 | 通过标识、最高候选分数、规则说明 | 注册艺术品或重新选择 |
| 比对失败 | 失败标识、候选作品、CLIP/ViT 分数 | 重新选择或申请复核（MVP） |
| 登记成功 | 登记编号、作品名称、登记时间 | 完成 |

## 10. 数据字段

### 用户输入

- 作品图片：必填。
- 作品名称：必填。
- 艺术家姓名：必填。
- 创作年份：必填。
- 作品媒介：必填。
- 作品说明：选填，后续版本考虑。
- 原创及授权声明：必填。

### 系统生成

- 文件哈希值。
- CLIP、ViT 嵌入及模型版本。
- 候选艺术品列表和相似度。
- 最终判定、阈值版本和判定时间。
- 登记编号和登记时间。

## 11. 验收标准

1. 用户可以选择本地图片并看到预览。
2. 未上传图片或缺少必填资料时，不能提交比对。
3. 用户可以体验通过和失败两种模拟结果。
4. 失败状态至少展示一条候选艺术品及两个模型分数。
5. 通过状态允许完成模拟登记并生成登记编号。
6. 页面可在桌面和手机宽度下正常使用，文字和控件不重叠。
7. 页面不依赖后端或构建工具，直接打开 `index.html` 即可运行。

## 12. 风险与保护措施

- 图像相似不等于侵权：界面和政策必须避免将模型输出表述为法律结论。
- 误报可能阻止原创作品登记：正式产品应提供人工复核和申诉路径。
- 漏报可能造成重复登记：应保留事后复查及登记撤销机制。
- 艺术作品可能包含敏感或未公开内容：需要明确存储期限、访问权限和删除政策。
- 模型对不同风格和媒介的表现不同：需要按数据域持续评估和校准。
- 对抗性修改可能规避检测：后续需要结合文件哈希、局部特征和人工判断。

## 13. 概念技术架构

```text
Web 上传页面
    -> 图片存储与元数据 API
    -> CLIP / ViT 嵌入服务
    -> 向量数据库检索候选作品
    -> 双阈值规则与人工复核策略
    -> 艺术品登记数据库
```

## 14. 概念验证指标

- 80% 以上测试用户无需解释即可完成上传和比对。
- 90% 以上测试用户能正确区分“未发现相似作品”与“已证明原创”。
- 用户能在 10 秒内找到登记失败的原因和候选作品。
- 用户对上传未公开作品的数据处理方式没有关键疑问。

## 15. 下一步决策

1. 产品是否定位为“登记前重复检测”还是“原创权属证明”？建议先选择前者。
2. 检测失败是否直接阻止登记，还是进入人工复核？建议进入人工复核。
3. 技术分数是否直接展示给艺术家？需要用户测试后决定。
4. 首批数据库采用 ArtBench、WikiArt 研究数据，还是只使用获得授权的真实登记作品？正式产品必须明确数据授权。
